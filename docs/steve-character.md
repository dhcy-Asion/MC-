# 第四角色：需求与验证记录

本记录对应 2026-10-04 用户确认的第一轮功能需求。开发优先验证新增第四个原生
F1 可玩角色；M1 文档与诊断基线已完成。用户最新同意先让背包独立可用，原生角色
研究保持未完成，新增 Steve、可见手持和生存战斗分别验收。
当前阶段与检查结果见 [progress.md](progress.md)。已发布建造／合成插件仍没有史蒂夫人物模型。

## 已确认的目标

- 保留克里夫、达米安和翁卡，按住 F1 的角色选择中新增史蒂夫。
- 史蒂夫使用 MC 的人物外观，不能穿戴红沙装备，可以穿戴 MC 装备。
- 史蒂夫采用 MC 生存攻击、护甲和受伤规则；心形血量必须反映真实 MC 生命值。
- 后续背包修改：每种物品自由领取一组，数量由 MC 原版最大堆叠决定，放置／使用消耗。
- 所有 MC 物品可选择和手持；第一阶段接入方块放置，其他物品功能逐步实现。
- 用户曾确认原版三人均已解锁；本轮确认切到达米安，翁卡暂时无法切换，行为未验证。

## 第四角色的验收条件

1. F1 菜单保留原版三人，增加独立的史蒂夫选项。
2. 切换后拥有独立的角色身份、控制权和状态，不能只是替换某个原版角色模型。
3. 回切原版人物后，原有装备、外观和角色状态保持正确。
4. 史蒂夫的装备、血量和存档独立；重载、死亡、骑乘和任务强制切回克里夫时不串状态。
5. 再接入模型、MC 装备限制和伤害桥接。只有模型预览、NPC 生成或心形覆盖层不算通过。

## 资产路径的研究结论

MC 1.21.1 客户端 JAR 中包含 Steve 皮肤，人物几何由程序生成，没有可直接导入的
OBJ／FBX。可以创建与 MC 几何一致的模型，但仍需解决红沙骨骼、动画和手持物绑定。
原版游戏文件和皮肤留在本机下载目录，不随本仓库发布。

[CDMW 的新增资产代码](https://github.com/Ratty123/CDMW-Full/blob/787680f97502522e90ec3dd1ea1889ca86452985/cdmw/core/archive_entry_addition.py)
提供新增归档记录的路径；上游报告新增模型等资源已经加载，这并非本机验证。
其 [角色外观替换](https://github.com/Ratty123/CDMW-Full/blob/787680f97502522e90ec3dd1ea1889ca86452985/cdmw/ui/archive_browser/mesh_swap_scope_dialog.py)
修改现有外观，不能证明新角色注册。当前
[模型导入说明](https://github.com/Ratty123/CDMW-Full/blob/787680f97502522e90ec3dd1ea1889ca86452985/cdmw/ui/new_item/README.md)
要求现有目标骨骼，不提供外部骨名和动画重定向。

[Character Creator 的角色枚举](https://github.com/Khione95/Crimson-Desert-Character-Creator/blob/b845222f771df8fb70fc720e191c609655480fb7/CharacterCreator/CharacterCreator/characters.h)
只有原版三人，其角色表读写针对已有记录。没有找到项目自身许可证，本次仅研究，
未复制其插件代码。现有 World Builder 的 NPC 生成与 `.app_xml` 预览也不是第四人物接口。

## 下一步判定

先在当前 EXE 上验证受控人物身份、F1 请求的参数、名单来源和角色创建生命周期。
管理器中的场景人物数量不能当作 F1 可选角色数量，源码中推测的角色标签也不能
当作原生 ID。未核实的原生函数不执行，未核实的指针不写入。

本机诊断事实、静态候选与未知项已归档在 [progress.md](progress.md)。原始内存地址、
进程信息和本机路径保留于忽略上传的 `runtime/`，公开记录只包含必要的摘要。
