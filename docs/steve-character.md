# 史蒂夫、方块、装备和分发：需求与验收

## 2026-10-08 最新要求（覆盖动作、装备与战斗范围）

用户更新持续目标：启用 mod 时角色完整变成 MC 的史蒂夫，不能使用原游戏的任何
装备，只能使用 MC 装备；点击控制栏某个物品后，该物品进入背包；攻击完全改为
MC 模式，单击可击退敌人。用户进一步明确角色动作系统也使用 MC 的动作。
这覆盖 2026-10-06 的“两套装备／保留红沙战斗”及此前沿用红沙动作的约定。
仍复用当前受控身份，禁用／卸载后恢复原外观及原装备，保留原存档；全方块、原 UI、
真实状态 HUD 和分发的其他要求保持。新要求没有将生命值来源改为独立 MC 生存生命。

| 要求 | 本轮验收条件 | 当前状态 |
| --- | --- | --- |
| 完整且持续的 Steve | 正确头身、四肢、皮肤、MC 动作，原 Armor／Hair／Beard 及背部装备不混叠；启用自动应用，重载、死亡和强制角色切换保持；禁用恢复 | 未完成；最新身体原材质对照中左手可见、身体四肢在观测姿势下对齐；头主颜色对照中位置正常、正确MC五官未出现，背部原装备仍在；两包均已恢复 |
| MC 动作系统 | 使用固定 MC 版本实际动作状态与姿态算法；站立、转头、走跑、跳跃、蹲伏、挥击及持物／使用状态与阶段时序一致；直臂直腿保持 MC 刚体动作，红沙连招和肘膝动画不再驱动 Steve；输入、重载、停用恢复分别验收 | 未实现；现有导出是静态几何，红沙蒙皮／合成弯曲不算 MC 动作。固定客户端算法已可本地读取，但没有经过当前 EXE 验证的受控 owner 姿态应用入口 |

| MC 单击攻击／击退 | 左键一次产生一次 MC 攻击，命中实际敌人后有实际伤害及方向正确的击退；空挥、遮挡、距离和攻击间隔正确；菜单点击不攻击，停用后恢复；MC 装备效果／耐久与库存一致 | 未实现；没有敌人命中、伤害、击退和原攻击抑制的已验证接口 |
| MC 第三人称装备显示 | 所选 MC 物品在手中，MC 护甲在对应部位，切换／卸装／重载正确；图标或固定模型不能代替使用效果 | 未实现；原生 socket／装备资源绑定待验证 |

背包在这里指已有的 **MC Mod 背包**，不是红沙原生装备背包。物品目录负责领取，
底部九格／36 格库存负责选择；当前领取不会自动改变选中格。不能把“已领取”“已选中”
当作手持、穿戴或攻击完成。现有非方块“消耗”仅扣库存，不能当作装备使用或 MC 战斗。

四格护甲存储使用固定 MC 1.21.1 的 Equipment、EquipmentSlot 和绑定附魔效果；
支持正常人体穿戴物、鞘翅与可戴头部，动物BODY与手持物不走此接口。完整组件随
物品转移／保存，护甲存储不在36格背包计数中重复计算。目前没有真实玩家实体，
不提供创造模式解除绑定豁免、护甲属性或原生应用，返回两项Applied=false。
检查摘要见[equipment-validation.json](equipment-validation.json)。

推进顺序：身体及 MC 头部贴图对照已实测并退出恢复；先离线核对头UV／材质通道，
再完成 Steve 装配与原装备隔离；MC 动作另建固定官方算法的离线姿态基准，不能以
离线输出替代受控人物的实际动作应用与恢复验收。
M6a 补点击领取的游戏内验收；M5a 先证明实际敌人目标与一次攻击／击退，再接 MC
武器、间隔及耐久。原生目标／调用未验证前，不用编辑器移动 NPC 代替击退。

## 2026-10-04 旧范围：可逆史蒂夫模式

- 可用独立菜单或快捷键，用户已接受复用当前红沙角色的移动与控制。
- 切入后显示与 MC 一致的史蒂夫模型，并能使用方块和 MC 装备；切出恢复原外观。
- 验收实际角色的模型、动画、装备绑定与恢复，不以离线 glTF 或屏幕贴图作为完成。
- 独立第四身份和 MC 生存规则仍可作为长期目标，不是本轮切换入口的要求。

## 原始长期目标

- 保留克里夫、达米安和翁卡，按住 F1 的角色选择中新增史蒂夫。
- 史蒂夫使用 MC 的人物外观，不能穿戴红沙装备，可以穿戴 MC 装备。
- 史蒂夫采用 MC 生存攻击、护甲和受伤规则；心形血量必须反映真实 MC 生命值。
- 后续背包修改：每种物品自由领取一组，数量由 MC 原版最大堆叠决定，放置／使用消耗。
- 所有 MC 物品可选择和手持；第一阶段接入方块放置，其他物品功能逐步实现。
- 用户曾确认原版三人均已解锁；本轮确认切到达米安，翁卡暂时无法切换，行为未验证。

## 独立第四角色的后续验收条件

1. F1 菜单保留原版三人，增加独立的史蒂夫选项。
2. 切换后拥有独立的角色身份、控制权和状态，不能只是替换某个原版角色模型。
3. 回切原版人物后，原有装备、外观和角色状态保持正确。
4. 史蒂夫的装备、血量和存档独立；重载、死亡、骑乘和任务强制切回克里夫时不串状态。
5. 再接入模型、MC 装备限制和伤害桥接。只有模型预览、NPC 生成或心形覆盖层不算通过。

## 资产路径的研究结论

MC 1.21.1 客户端 JAR 中包含 Steve 皮肤，人物几何由程序生成，没有可直接导入的
OBJ／FBX。项目已从固定官方模型生成实际几何／UV；动作同样由客户端程序计算，
PlayerEntityModel／BipedEntityModel 包含 setAngles、animateModel、animateArms 及持物／
蹲伏分支。当前资产导出只调用静态模型构造，glTF 没有 animations，不能据此称动作
已导出或应用。复用官方算法后仍须解决红沙受控骨骼姿态应用、状态时序和手持绑定。
原版游戏文件和皮肤留在本机下载目录，不随本仓库发布。
