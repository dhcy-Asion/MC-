# 史蒂夫、方块、装备和分发：需求与验收

## 2026-10-06 最新要求（覆盖旧范围）

用户本次提供 MC 心形／饥饿／经验条和九格快捷栏图片，要求保留原角色 UI，并在
角色下方新增相似 UI。以下范围覆盖旧“可手动切回”和“不能穿红沙装备”的产品要求；
旧记录只保留研究依据。固定 MC 版本仍为 Java 1.21.1。

用户已确认：“永久”指 mod 启用期间自动持续生效并跨重载，禁用或卸载后恢复原外观；
心形血量显示红沙真实血量，继续红沙战斗规则，不建立独立 MC 生存生命。
不能直接破坏原版保存以达到持续切换效果。
当前没有自动 Steve 切换开关，也没有装备接口；上表为待实现验收，不能据此声称完成。
本轮九格是可独立验证的第一步，并不完成整张图片中的生存状态栏。
离线资产进一步提供六种基线的 14 项真实模型，以及保留四个 LOD 的 Steve 原生 PAC 候选；
原生材质、骨骼动画/贴合、装备和外观生命周期尚未通过。步骤见 [asset-pipeline.md](asset-pipeline.md)。

F1 可玩角色；M1 文档与诊断基线已完成。用户此前同意先让背包独立可用，最新一轮
再次优先要求史蒂夫、MC 外观、方块和 MC 装备使用。随后用户明确接受不走 F1 的
“史蒂夫模式”，复用当前角色移动／控制，切回恢复原外观；独立第四身份不再是本轮门槛。
原生角色研究保持未完成，模式切换、可见装备和生存战斗分别验收。
当前阶段与检查结果见 [progress.md](progress.md)。已发布背包／建造插件仍没有史蒂夫人物模型。

## 2026-10-04 旧范围：可逆史蒂夫模式

- 可用独立菜单或快捷键，用户已接受复用当前红沙角色的移动与控制。
- 切入后显示与 MC 一致的史蒂夫模型，并能使用方块和 MC 装备；切出恢复原外观。
- 验收实际角色的模型、动画、装备绑定与恢复，不以离线 glTF 或屏幕贴图作为完成。
- 独立第四身份和 MC 生存规则仍可作为长期目标，不是本轮切换入口的要求。

## 原始长期目标

- 保留克里夫、达米安和翁卡，按住 F1 的角色选择中新增史蒂夫。
- 史蒂夫使用 MC 的人物外观，不能穿戴红沙装备，可以穿戴 MC 装备。
- 史蒂夫采用 MC 生存攻击、护甲和受伤规则；心形血量必须反映真实 MC 生命值。
- 后续背包修改：每种物品自由领取一组，数量由 MC 原版最大堆叠决定，放置／使用消耗。
- 所有 MC 物品可选择和手持；第一阶段接入方块放置，其他物品功能逐步实现。
- 用户曾确认原版三人均已解锁；本轮确认切到达米安，翁卡暂时无法切换，行为未验证。

## 独立第四角色的后续验收条件

1. F1 菜单保留原版三人，增加独立的史蒂夫选项。
2. 切换后拥有独立的角色身份、控制权和状态，不能只是替换某个原版角色模型。
3. 回切原版人物后，原有装备、外观和角色状态保持正确。
4. 史蒂夫的装备、血量和存档独立；重载、死亡、骑乘和任务强制切回克里夫时不串状态。
5. 再接入模型、MC 装备限制和伤害桥接。只有模型预览、NPC 生成或心形覆盖层不算通过。

## 资产路径的研究结论

MC 1.21.1 客户端 JAR 中包含 Steve 皮肤，人物几何由程序生成，没有可直接导入的
OBJ／FBX。可以创建与 MC 几何一致的模型，但仍需解决红沙骨骼、动画和手持物绑定。
原版游戏文件和皮肤留在本机下载目录，不随本仓库发布。
